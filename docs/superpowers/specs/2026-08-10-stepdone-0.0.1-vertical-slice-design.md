## 1. 目标与非目标

### 1.1 目标

交付**内部可演示的垂直切片**：用户可从首页完成竞品分析主链路，经预览与 mock 付费解锁后，使用轻量编辑器、质量检查、能力报告，并获得假 PDF/PPT 导出；AI 与微信为 mock，但**项目状态机、订单权益闸门、异步任务与恢复**按技术文档真实边界实现。

### 1.2 完成定义（演示成功）

1. 新用户：首页 → 填任务 → mock 登录并恢复表单 → 六步均可点完成 → 成果预览 → mock 付费解锁 → 轻编辑 / 质量 / 能力 → 假 PDF（专业套餐含假 PPT）。
2. 刷新或关闭页面后，项目可从 MySQL 状态恢复；AI 任务不因关页而丢弃。
3. 全程无「无法继续且无出路」的死胡同。
4. 验收含：手动主链路 + Playwright 一条 E2E + 状态机/权益/幂等关键单测。

### 1.3 非目标（本切片明确排除）

- 微信小程序原生壳 / WebView
- 真微信登录、真微信支付、真短信验证码
- 真混元 / DeepSeek 调用；真网页搜索与抓取
- 运营/管理后台
- 共享链接、项目复制、语音输入
- 多项目模板（营销/求职等仅展示「即将开放」）
- 真 Export 排版引擎、多版本 diff、长文本自动合并
- Kubernetes、复杂微服务、向量库、自动续费

### 1.4 实现策略

采用**骨架先行**：先 monorepo、Prisma、模板引擎、Outbox、假 Worker、mock 鉴权/支付闸门，再用 fixture 接入 UI。

## 2. 架构与仓库边界

### 2.1 仓库结构（首期）

```
stepdone/
├── apps/
│   ├── web/                 # Next.js App Router（BFF + UI）
│   └── agent-worker/        # BullMQ 消费者；fixture 节点执行
├── packages/
│   ├── database/            # Prisma schema / client / repos
│   ├── domain/              # 枚举、状态、错误码
│   ├── schemas/             # Zod 输入输出
│   ├── project-engine/      # 模板加载 + 状态转换（含 competitor-analysis@1 定义文件）
│   ├── agent-core/          # Node 接口、租约、幂等、校验钩子
│   ├── payments/            # 订单 / 权益 / mock 支付回调
│   ├── auth/                # Session + mock 登录
│   └── config/              # 环境变量解析
├── infrastructure/
│   └── docker/              # docker-compose: MySQL 8 + Redis
├── docs/
├── pnpm-workspace.yaml
└── turbo.json
```

首期不建：`miniprogram`、独立 `export-worker`（导出走 agent-worker 的 `export` 队列 + 样例文件）、独立 `ui` / `design-tokens` 包（tokens 暂放 `apps/web`）。

Outbox Dispatcher：挂在 `agent-worker` 进程内的定时循环，不单独成 app。

### 2.2 运行时关系

```
浏览器
  → Next.js (RSC + Route Handlers + SSE)
      → MySQL（业务事实源）
      → Redis（BullMQ / PubSub / 短时 ticket）
      → 同事务写入 agent_runs + outbox_events

Outbox 投递循环
  → BullMQ

agent-worker
  → 租约 → 执行 fixture 节点 → Zod 校验 → 持久化
  → project_events → Redis → SSE / 轮询降级
```

### 2.3 架构原则

1. MySQL 是唯一业务事实源；Redis 不保存最终项目/支付/权益状态。
2. 队列消息只传 ID 引用（如 `agentRunId`、`projectId`、`stepRunId`、`nodeCode`、`schemaVersion`）。
3. 是否付费、是否跳过用户判断、是否完成项目等，由 `project-engine` 与业务服务决定，不由「模型」决定。
4. Mock 可替换：`MockModelProvider` / `MockPaymentProvider` / `MockSearchTool` 与未来真实现同一接口；切片期只启用 Mock。

### 2.4 现有代码迁移

将根目录 Create Next App（Next 16 + React 19）迁移为 `apps/web`；根目录改为 pnpm workspace 脚本。本地依赖：`docker compose` 启动 MySQL 8 + Redis。

## 3. 模板步骤与状态机

### 3.1 模板

- 唯一模板：`competitor-analysis`，版本 `1`。
- 创建项目时锁定 `templateVersionId`；历史版本不可原地修改。
- 定义文件：`packages/project-engine` 内 `templates/competitor-analysis/v1.ts`（步骤码、闸门、input/output schema 引用）。

### 3.2 UI 六步与内部节点

| UI 六步 | 内部 nodeCode（顺序） | 用户闸门 |
|---|---|---|
| 1 明确目标 | `DEFINE_OBJECTIVE` | 任务定义表单提交 |
| 2 制定计划 | `CREATE_PLAN` → 用户确认 | 确认计划 |
| 3 选择竞品 | `SELECT_COMPETITORS` | 确认 3～5 个竞品（专业权益可至 8） |
| 4 搜集资料 | `RESEARCH_SOURCES` | 浏览/排除来源后继续 |
| 5 形成判断 | `SELECT_DIMENSIONS` → `BUILD_MATRIX` → `USER_JUDGMENT` | 维度确认；判断操作 |
| 6 成果交付 | `GENERATE_PREVIEW` → `PAYMENT_GATE` → `GENERATE_REPORT` → `QUALITY_REVIEW` → `FINAL_CONFIRMATION` → `EXPORT` → `ABILITY_REPORT` | 未付费不可进完整报告 |

### 3.3 项目状态

`DRAFT` → `ACTIVE` ⇄ `WAITING_USER` ⇄ `AI_PROCESSING` → `PAYMENT_REQUIRED` →（支付成功）继续 `ACTIVE` → `QUALITY_REVIEW` → `COMPLETED`  

另保留：`ARCHIVED` / `FAILED` / `CANCELLED`。

### 3.4 步骤状态

`PENDING` → `QUEUED` → `RUNNING` →（`WAITING_USER`）→ `VALIDATING` → `SUCCEEDED`  

失败：`FAILED_RETRYABLE` / `FAILED_FINAL`；可 `CANCELLED`。

### 3.5 硬规则

1. 上一步未 `SUCCEEDED` 不能 start 下一步（支付成功后从 `PAYMENT_GATE` 放行除外）。
2. `requiresUserDecision` 节点禁止 Worker 自动写入最终决策；只能返回 `waiting_user`。
3. 无对应权益时拒绝执行 `GENERATE_REPORT` 及之后节点。
4. 所有状态转换写入 `project_events`。
5. `GENERATE_PREVIEW` 成功后项目状态为 `PAYMENT_REQUIRED`。

### 3.6 Fixture（假 Worker）

- AI 节点延迟约 1～3s；研究节点约 5～8s；返回符合 Zod 的半固定 JSON（注入项目名、分析对象）。
- 研究节点写入 6～12 条 `sources`。
- 开发环境可保留强制失败开关；默认主链路不失败。

## 4. 数据模型与 API

### 4.1 核心表

**身份**：`users` · `user_identities` · `user_sessions`  
- `publicId`：ULID；identity provider 含 `MOCK`（预留微信/短信）

**模板**：`project_templates` · `project_template_versions` · `project_template_steps`（seed `competitor-analysis@1`）

**项目**：`projects`（含 `revision`、`currentStepCode`、`status`、`metadata_json`）· `project_step_runs` · `project_decisions` · `project_events`

**Agent**：`agent_runs` · `model_usages`（fixture 也记假用量）· `outbox_events`

**来源 / 成果**：`sources` · `citations` · `artifacts` · `artifact_versions`（Block JSON）· `exports`  
- 首期不做 `source_snapshots` 全文存储；来源以 URL + 摘要元数据为主。

**交易**：`products` · `orders` · `payment_transactions` · `entitlements` · `entitlement_transactions`  
- Seed：`STANDARD_PROJECT` = 2900 分，`PRO_PROJECT` = 5900 分。

**能力**：`skill_dimensions` · `skill_assessments`

规范：金额用分；时间 UTC；文件不进 MySQL。

### 4.2 权益差异（标准 vs 专业）

| 能力 | 标准 ¥29 | 专业 ¥59 |
|---|---|---|
| 完整报告 + PDF 假导出 | 有 | 有 |
| PPT 假导出 | 无 | 有 |
| 竞品上限 | 5 | 8 |
| `RESEARCH_RETRY` / `REPORT_REGENERATE` | 无 | 各 1 次（假 Worker） |
| 「更深度研究」 | — | 不同 fixture 文案，非真更多搜索 |

### 4.3 API 约定

统一响应：`{ success, data | error, requestId }`；对外 ID 使用 `publicId`。

**Auth**：`POST /api/auth/mock-login` · `POST /api/auth/logout` · `GET /api/auth/me`

**游客草稿**：表单存 `sessionStorage`（或等价客户端 persist）；登录成功后 `POST /api/projects` 提交草稿并创建项目（不维护匿名服务端项目）。

**主链路 API（子集）**：

| 区域 | 端点 |
|---|---|
| 项目 | `POST/GET/PATCH /api/projects`，`GET/PATCH/DELETE /api/projects/:id`，归档按需 |
| 步骤 | `GET .../steps`，`POST .../steps/:code/start\|input\|decision\|retry` |
| 进度 | `GET .../events`（SSE），`GET .../status` |
| 来源 | `GET/POST/PATCH` sources |
| 成果 | artifacts CRUD 子集，`quality-check`，`exports` |
| 支付 | `POST /api/orders`，`POST /api/payments/mock/confirm`，`GET /api/orders/:id` |
| 权益 | `GET /api/entitlements` |

权限：项目类 API 校验 `project.userId === currentUser.id`；导出与完整报告再校验权益。

自动保存：`PATCH` 带 `revision`；冲突返回 `409 PROJECT_REVISION_CONFLICT`。

### 4.4 Mock 支付闸门（必须为真业务路径）

1. 客户端只传 `productCode`。
2. 服务端按 `products` 定价创建订单。
3. `POST /api/payments/mock/confirm`（仅当 `MOCK_PAYMENTS=1` 或非 production）模拟回调。
4. 同一事务：订单 `PAID` + 支付流水 + 发放权益 + 权益流水 + Outbox（推进 `GENERATE_REPORT`）。
5. 禁止前端仅设 `paid=true` 解锁。

## 5. 页面信息架构与交互

### 5.1 路由

- 营销：`/` · `/pricing` · `/examples` · `/help` · `/privacy` · `/terms`
- 认证：`/login`
- 应用：`/projects` · `/projects/new` · `/projects/[id]/{plan,competitors,sources,dimensions,matrix,decisions,preview,report,quality,ability}` · `/orders/[id]` · `/settings`
- 移动底栏：任务 | 项目 | 成果 | 我的

### 5.2 与 UI 稿对齐方式

**结构对齐**（信息架构、关键文案、主按钮、三栏/单列/底栏）；视觉使用简洁蓝色主色 design tokens；不像素级抠稿。

付费后薄实现：

- **编辑器**：章节目录 + 极简 Tiptap（段落/标题/基础列表，不做完整图表体系）+ 右侧 mock AI 建议与「采用」（AI 不直接覆盖）。
- **质量**：分数环 + 问题卡片状态流转（补充来源 / 修改表述等可改状态）。
- **能力**：基于真实计数（判断次数、修改次数等）+ 雷达 + fixture 解读。

### 5.3 响应式

- `<768`：单列、底栏、底固定主按钮、AI Bottom Sheet、矩阵可卡片视图
- `768–1199`：步骤折叠、AI 抽屉
- `≥1200`：左 240 / 中自适应 / 右 360

### 5.4 关键交互

1. 游客填表 → 登录闸门 → 恢复草稿 → 创建项目并入队 `CREATE_PLAN`。
2. AI 进行中可离开；首页「继续项目」；进入后 SSE + `/status` 恢复。
3. 保存态文案：正在保存… / 已自动保存 / 保存失败重试 / 冲突双选（保留我的 / 用云端）。
4. 自动保存触发：防抖约 1s、失焦、切步、每 30s。
5. AI 导师：一次一个关键问题、有限选项、克制语气（遵循 PRD 12 节）。

### 5.5 文件上传

首期以**添加 URL / 使用 fixture 来源**为主；不做本地大文件二进制上传与 COS 联调（接口可预留）。

### 5.6 导出

创建 `exports` → 入队 → 假处理数秒 → 提供静态样例 PDF；专业套餐可见 PPT 并提供样例文件。下载链接短时、需登录与权益校验（本地可用受控静态路径模拟签名 URL）。

- `GET /api/projects/:projectId/events`：`text/event-stream`；支持心跳、权限校验；Last-Event-ID 可做瘦身版。

## 7. 错误处理与安全

### 7.1 错误与恢复

| 场景 | 行为 |
|---|---|
| 可重试失败 | `FAILED_RETRYABLE` + 重试；幂等键含 `inputVersion` |
| 最终失败 | 保留已写结果；引导修改或从稳定步重来 |
| 取消任务 | 停止后续；保留已完成部分 |
| 保存冲突 | 409 + 双选，不自动 merge |
| 支付未完成 | 保留预览与项目；可重付/换套餐 |
| SSE 断 | 重连 + 轮询降级 |
| Redis 短暂故障 | MySQL 与 Outbox 不丢任务 |
| 重复提交 | 按钮 loading + 幂等键 |
| 来源不足 | 不阻断；标记限制并允许继续 |

### 7.2 安全（薄但必须）

- HttpOnly Session Cookie；mock 登录走同一会话模型。
- 资源级所有权校验。
- 金额只信服务端产品表。
- mock 支付接口禁止在未显式开启时用于 production。
- 日志禁止完整 session / 密钥；记录 prompt code/version 而非未脱敏长文本。
